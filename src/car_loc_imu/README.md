# car_loc_imu — 方法三: 只用 IMU (慣性推算 + 抗漂移)

```
/imu ──> 扣重力 ──> 扣零偏 ──> EKF 遞推 ──┬── ZUPT   靜止時速度 = 0
          (b0 + Gauss-Markov)             ├── ZARU   靜止時陀螺儀讀到的全是零偏
                                          ├── 零加速度 靜止時水平加速度 = 0 -> 修 b_a
   靜止 = 原始讀數安靜                     ├── 位置錨定 停久了不要隨機遊走
        + 用估計的零偏/速度再確認          └── NHC    車不會橫著走 -> 側向速度 = 0
                                                         v
          /imu_loc/odom + /imu_loc/pose + /imu_loc/imu_corrected + TF map->base_link
```

**現在的狀態 (2026-10-06):** 零偏模型是「開機常數 + Gauss-Markov」, 參數由
`imu_fit_noise` 對靜止資料擬合。Isaac 十二趟 (各約 35 m, 注入已知零偏) 的
平均: 位置 RMS 0.52 m (改之前 1.81 m), 陀螺零偏去除 95%, 加速度零偏去除
71–76%。完整說明、跟改之前的對照、執行順序在
[report_imu_explained.md](../../report_imu_explained.md)。

**這個 package 只訂閱 `/imu`。** 沒有地圖、沒有雷射、沒有相機, 也不 import
任何其他 package。

## 先講清楚: 純 IMU 一定會漂

加速度的誤差要**積分兩次**才變成位置, 所以一個固定的加速度偏差 b 在 t 秒後是
`0.5*b*t²` 的位置誤差 —— 0.01 m/s² (很小的偏差) 在 60 秒後就是 **18 公尺**。
這不是參數沒調好, 是數學。這個 package 能做的是把漂移的**成長速度**壓下來,
不是消除它。要真的不漂就需要一個絕對量測 —— 那是方法一 (相機) 與方法二 (LiDAR)
在做的事。

還有一件事: 純 IMU **不知道自己在世界的哪裡**, 它只能從一個給定的起點
(`initial_pose`) 開始推。方法一與方法二都能自己找到自己, 方法三不行。

## 用法

```bash
ros2 launch car_loc_imu imu_loc.launch.py
ros2 launch car_loc_imu imu_loc.launch.py evaluate:=true

# 真車 (6 軸 IMU, 沒有絕對姿態)
ros2 launch car_loc_imu imu_loc.launch.py use_sim_time:=false \
    imu_topic:=/imu/data gravity_mode:=complementary yaw_source:=gyro

# base_link 照 REP-103 (+X 是車頭) 的車; 這台 car.usd 不是, 預設已經是 -90
ros2 launch car_loc_imu imu_loc.launch.py forward_deg:=0.0

# A/B: 關掉抗漂移機制看差多少
ros2 launch car_loc_imu imu_loc.launch.py evaluate:=true \
    enable_zupt:=false enable_nhc:=false
```

> **開始之前先讓車子停著幾秒。** 開機靜止校正要在那幾秒裡把零偏量掉 —— 這是
> 最便宜也最有效的一步。沒做的話那個零偏會被積分兩次, 幾十秒就是幾公尺。
> 車子一開始就在動的話節點會等 10 秒然後印警告, 零偏當 0 開始推。

## 離線驗證 (不需要 ROS, 不需要 Isaac)

兩支, 要一起看:

```bash
cd src/car_loc_imu
python3 test/test_ins.py                        # 合成資料 (假設都成立的乾淨情況)
python3 test/replay_bag.py <bag 目錄>            # **真的 Isaac 資料** 的 A/B
python3 test/replay_bag.py <bag 目錄> --measure  # 從 bag 量出該用的參數
```

`replay_bag.py` 直接讀 rosbag2 的 sqlite3 (自己解 CDR, 不需要 ROS), 把 `/imu`
餵進濾波器, 跟 bag 裡的 `/odom` 比。**參數不要用猜的** —— 錄一次 bag, 之後
所有 A/B 兩秒跑完, 而且每次餵的是完全一樣的資料。

```bash
ros2 bag record -o my_run /imu /odom       # 跑一輪測試, 錄下來
python3 test/replay_bag.py my_run --measure
```

`--measure` 量四件事, 每一件都對應一組參數:

| 量什麼 | 決定 |
| --- | --- |
| ground truth 的行進方向 vs yaw | `forward_deg` (NHC 要約束哪一軸) |
| 靜止時的雜訊底線 | `still_gyro` / `still_var` / `still_acc` |
| 加速度殘差 **vs 角速度** | `sigma_acc` / `sigma_acc_omega` |
| IMU 離旋轉中心多遠 | 要不要補向心加速度 (car.usd 量到 0.6 mm, 不用) |

## 四道防線值多少 (離線實測)

60 Hz, 60 秒, 8 字形軌跡每 15 秒平滑停 3 秒。陀螺零偏 0.004 rad/s,
加速度零偏 (0.02, -0.015) m/s²。表格是位置誤差。合成資料, 沒有側滑 ——
NHC 在這裡**完全成立**, 這是它最有利的情況。

**[A] Isaac 情境 —— IMU 給精確姿態 (重力扣得準, yaw 有絕對值), 車身水平**

| 開了什麼 | RMS | p95 | 最大 |
| --- | --- | --- | --- |
| 純積分 (什麼都不開) | 4.84 m | 9.57 m | 10.31 m |
| + ZUPT / ZARU | 0.50 m | 0.81 m | 0.86 m |
| + NHC (只有 NHC) | 0.08 m | 0.13 m | 0.16 m |
| **全開** | **0.13 m** | 0.21 m | 0.21 m |

**[B] 真車情境 —— 6 軸 IMU: yaw 只能靠陀螺儀積分, 傾角靠互補濾波**

| 開了什麼 | RMS | 最大 |
| --- | --- | --- |
| 完全不修 (連傾角都不修) | 104 m | 194 m |
| + ZUPT / ZARU | 3.88 m | 17.26 m |
| **全開** | **0.69 m** | 1.16 m |

**[C] 車身固定傾斜 2 度**

| | RMS | 最大 |
| --- | --- | --- |
| 全開, 互補濾波估傾角 | 2.89 m | 6.06 m |
| 全開, IMU 給精確姿態 | 0.48 m | 1.86 m |

**[CC] 車頭軸給錯 —— `car.usd` 的 base_link 是 +X 朝左、車頭 -Y**

| NHC 的軸 | RMS | 最大 |
| --- | --- | --- |
| 給對 (`forward_deg: -90`) | **0.14 m** | 0.24 m |
| 給錯 (照 REP-103 當 0) | 3.68 m | 9.26 m |
| 同一條軌跡, 乾脆不開 NHC | 0.57 m | 0.99 m |

**軸給錯比不開 NHC 還糟 6 倍。** 因為它不是「少一個約束」而是「約束錯的東西」:
把**前進速度**當成側滑去修, 同時真正的側向完全沒人管。

> 這幾張表是現在的預設 (`nhc_sigma = 2.0`) 量的。`nhc_sigma = 0.15` 的時候
> 這裡的數字比較好看 (「全開」0.03 m、6 軸 0.17 m), 因為合成資料沒有側滑;
> 但在有側滑的 Isaac 資料上 0.15 明顯比較差 (見「NHC 的份量」)。
> 兩邊衝突的時候以有側滑的資料為準。

四個結論:

0. **先確認車頭是哪一軸。** 這台車的 `base_link` 不照 REP-103 —— 它 +X 朝左、
   車頭是 -Y, 所以 `forward_deg: -90`。表 [CC] 是給錯的代價。要驗證的話拿
   ground truth 算 `atan2(dy, dx) - yaw`: 這台車量出來是 -90.0°
   (標準差 0.6°), REP-103 的車會是 0°。
1. **姿態誤差比零偏更致命。** 傾斜 1 度 = 0.17 m/s² 的假加速度 = 10 秒後 8.5 公尺。
   [B] 第一列的 104 m 就是「傾角完全不修」的代價 —— 陀螺儀雜訊讓傾角隨機遊走,
   0.06 度的傾角誤差就足以造成幾十公尺。
2. **NHC 是行駛中唯一有效的一項。** ZUPT 只在停車時有效。但它的份量不能給太重
   (見「NHC 的份量」)。
3. **上面的數字之所以好看, 是因為那條軌跡每 15 秒就停 3 秒。** 一直開不停的話
   ZUPT 完全不會觸發, 誤差就是自由累積。**純 IMU 撐得住多久, 取決於「多久停
   一次」, 不是取決於參數。**

## 五個機制各自在做什麼

**開機靜止校正。** 車子還沒動的時候把陀螺儀零偏、加速度計零偏、重力方向一次量掉。

**ZUPT (零速更新)。** 偵測到靜止就宣告「速度是 0」, 速度誤差歸零, 位置停止漂移。

> **陷阱: ZUPT 不能只看陀螺儀。** 等速直線行駛的車子角速度是 0、加速度也接近 0,
> 純慣性量測**分不出**「靜止」與「等速直線」。只看陀螺儀做 ZUPT, 車子一開直線
> 速度就被歸零, 位置直接停在原地。所以這裡的靜止判定同時看陀螺儀、加速度大小、
> 以及一段視窗內加速度的**變異數** (`still_var`) —— 真的靜止時只剩感測器雜訊,
> 行駛時輪子震動與路面起伏會讓變異數高一個數量級。
> 調參時看 status 那行的「靜止 xx%」跟實際停車比例對不對得上。

**ZARU (零角速更新)。** 靜止時陀螺儀讀到的東西全部是零偏, 直接拿來修 `b_g`。
這是 `yaw_source:=gyro` 時唯一能持續修正 yaw 漂移的機制。

**位置錨定。** 停超過 0.5 秒之後, 把位置釘在停下來的地方。ZUPT 把速度歸零了,
但位置的共變異數還是會慢慢長大變成隨機遊走; 錨定把它也按住。

**NHC (非完整約束)。** 車子不會橫著走, 所以**車體座標的側向速度應該是 0**。
這是輪式載具特有的免費量測, 而且行駛中一直有效。
注意 skid-steer 轉彎時這個假設會被違反, 所以角速度大於 `nhc_max_omega` 時
直接關掉, 而且每一筆的份量給得很輕 (`nhc_sigma: 2.0`, 見「NHC 的份量」)。

> **「側向」是哪一軸不能用猜的。** REP-103 說 `base_link` 的 +X 是車頭, 但
> `car.usd` **不是** —— 它 +X 朝左、車頭 -Y (`car_teleop/cmd_vel_bridge.py`
> 裡也寫著同一件事)。所以車頭軸由 `forward_deg` 給 (從 +X 量到車頭的角度,
> 這台車是 **-90**), NHC 約束的是垂直於它的那一軸。
> 給錯的話 NHC 會把**前進速度**當成側滑歸零 —— 估計裡的車幾乎不前進, 而真正
> 的側向完全沒有約束, 誤差自由累積。見表 [CC]: 給錯 3.68 m, 比不開 NHC
> (0.57 m) 還糟 6 倍。

## 過程雜訊要跟著角速度走

**這是最容易調錯、而且怎麼調單一數值都不會對的一個地方。**

拿 Isaac 的 bag 量「IMU 扣完重力的水平加速度」跟「ground truth 微分出來的
真實加速度」差多少 (`replay_bag.py --measure`):

| `|wz|` | 殘差 | 連續時間 (÷√60) |
| --- | --- | --- |
| < 0.2 rad/s | 0.064 m/s² | 0.008 |
| 1–2 rad/s | 0.27 m/s² | 0.034 |
| > 12 rad/s | 14.7 m/s² | 1.9 |

**差 230 倍。** 所以過程雜訊是
`sqrt(sigma_acc² + (sigma_acc_omega·|w|)²)`, 不是一個常數。給常數的話兩頭都錯,
而且錯的方向相反:

* 直線行駛時 P 被灌大幾十倍 → 速度偽量測 (ZUPT/NHC) 的增益逼近 1,
  **一次更新就把位置搬走好幾公尺**。而且 P 大 S 也大, 卡方閘門的 NIS 反而變小,
  完全擋不住。實測單步跳動最大 **27 公尺**, 同一步車子只走了 4 公分。
* 高速自旋時 P 又太小 → 正確的 ZUPT / NHC 被當成離群值擋掉。

兩道防線一起上:

| | 擋什麼 | 為什麼另一道擋不住 |
| --- | --- | --- |
| 卡方閘門 | 跟自己的不確定度比太離譜的量測 | P 一大 S 就跟著大, NIS 永遠過關 |
| `max_pos_correction` | 單次更新把位置搬超過 0.5 m | 卡方閘門對「合理但巨大」的修正沒意見 |

超過上限時是把**整個增益等比例縮小**, 不是截斷位置那兩維 —— 方向還是對的,
只是走短一點。共變異數用 Joseph form 更新, 它對任意增益都成立, 所以縮過的
增益仍然是一致的。

### 哪些偽量測該吃卡方閘門

| | 吃閘門? | 為什麼 |
| --- | --- | --- |
| ZUPT / ZARU / 零加速度 | **不吃** | 依據是**靜止偵測** —— 一個跟濾波器狀態無關的獨立判斷。拿閘門擋它等於「越迷路越拒絕修正」。實測 (6 軸 + ZUPT/ZARU): 吃閘門 64.7 m, 不吃 **3.9 m** |
| IMU 的絕對 yaw | **不吃** | 在 `orientation` 模式下量測比遞推可信。而且 `w·dt` 遞推本來就落後 `|w|·dt/2`, 20 rad/s 時是 0.17 rad —— 比 sigma 0.02 大一個數量級, 閘門會把**完全正確的量測**當離群值。實測擋掉 65%, 狀態 yaw 中位誤差 **61 度** |
| NHC | **吃** | 它是一個**假設**, 而 skid-steer 打滑時真的會壞掉, 沒有獨立依據可以事先判斷 |

### sigma_acc 要跟著 `gravity_mode` 走

| 模式 | `sigma_acc` | 為什麼 |
| --- | --- | --- |
| `orientation` | **0.03** | 姿態是精確的, 殘差就只剩感測器雜訊 |
| `complementary` | **0.35** | 傾角是**估**出來的, 那個估計誤差本身就是持續存在的假加速度 (傾斜 1 度 = 0.17 m/s²)。過程雜訊蓋不住它, NHC 就會一直被閘門擋掉。實測: 0.03 → 6.20 m, 0.35 → 2.54 m |

節點啟動時會檢查這一組有沒有配錯, 配錯會印警告。

## ZUPT 能做什麼、不能做什麼

> 這一節到「原地自旋 ZUPT」為止的數字是 2026-09 用 `spin12` bag、當時的設定
> (隨機遊走、沒有第二階段確認、`nhc_sigma` 0.15) 量的, 沒有用現在的程式重量。
> 結論 (ZUPT 只能讓誤差停止長大) 不受影響。

拿 `spin12` bag 量 13 次高速自旋 (峰值 15–23 rad/s), 每次自旋後車子都會停一下:

| | |
| --- | --- |
| ZUPT 有觸發的次數 | **10 / 13** |
| 觸發時 sigma | 8–22 m → **0.004 m** (立刻收斂) |
| 觸發後位置還在動 | 0.001–0.023 m (等於釘住了) |
| 13 次自旋**灌進去**的誤差 | **+30.0 m** |
| 停車**救回來**的誤差 | **−0.6 m** |

**ZUPT 有在動, 但誤差不會變準。** 這不是 bug, 是結構性的: ZUPT 是**速度**的
量測 —— 它說的是「你現在沒在動」, 所以能讓誤差**停止長大**, 但它完全不帶
「你在哪裡」的資訊。純 IMU 沒有任何絕對位置參考, **位置誤差是不可逆的**。
上表那些看起來像「救回來」的負值 (−6.86, −4.21…) 跟正值 (+9.42, +9.21…) 一樣多,
那是估計值在真值附近亂晃剛好穿過去, 不是修正。

要位置誤差真的變小, 只能靠一個絕對量測 —— 方法一 (相機) 或方法二 (LiDAR)。

沒觸發的那 3 次, 是因為**車子還在以 ~1 rad/s 慢慢轉** (`|gyro|` 中位 1.0 rad/s),
偵測器拒絕是對的 —— 那不是靜止。

### 觸發延遲

停車到 ZUPT 觸發之間有 **0.55–0.77 s** 的延遲, 那段時間估計還帶著自旋累積的
速度誤差在滑, 實測滑過 **2.65 m**。想靠縮短 `still_window` 來減延遲是**反效果** ——
誤判率跟著上升, 而行駛中誤觸發 ZUPT 的代價更大:

| `still_window` | 觸發率 | 誤判率 | 位置 RMS |
| --- | --- | --- | --- |
| 0.30 s (預設) | 49.5% | 6.1% | **14.32 m** |
| 0.20 s | 51.0% | 6.8% | 15.65 m |
| 0.15 s | 51.8% | 7.5% | 16.39 m |

### 原地自旋 ZUPT (`enable_spin_zupt`, 預設關)

ZUPT 要求陀螺儀也要小, 所以 skid-steer **原地打轉**時完全不會觸發 —— 但那時
平移速度確實是 0。偵測方法: `|w|` 夠大 **而且**視窗內水平比力接近 0
(繞圈行駛的話側向比力 = `v·w`, 不會小; 原地打轉才會)。

> 這裡有一個容易做錯的細節: 要**先把加速度向量平均起來再取長度**, 不是把
> 每一筆的長度平均。自旋時單筆的雜訊非常大 (實測 `|wz|>12` 時 std 14.7 m/s²)
> 但那是零均值的, 先平均向量雜訊才會抵消。實測同一批樣本:
> `mean(|a|) = 3.82` 但 `|mean(a)| = 0.28`。用前者的話門檻永遠過不了。

偵測本身很準 (85% 的觸發樣本車子真的沒在平移, 誤判時車速也只有 0.09 m/s),
**但端到端量不出好處** (RMS 14.32 → 14.18 m, 在雜訊裡), 所以預設關掉。
超過 `spin_omega_max` (6 rad/s) 更是有害 —— 60 Hz 撐不住那個轉速。
你自己的 bag 可能不一樣, `test/replay_bag.py <bag>` 會把開關兩列一起印出來。

## 靜止的第二階段確認

`StillDetector` 只看原始讀數的大小與變異數。路面平、感測器白雜訊又蓋過車體
震動的時候, 下面三種「車子其實在動」的情況它都會說靜止。`StillConfirm`
用濾波器自己估的零偏與速度把它們擋掉:

| 被誤判成靜止的情況 | 後果 | 怎麼擋 | 參數 |
| --- | --- | --- | --- |
| 平順的直線加減速 | 真實的加速度被當成加速度零偏 | 平均水平加速度 (扣零偏) 要夠小 | `still_acc_mean` |
| 高速自旋後的慢轉 | 真實的轉速被當成陀螺零偏 | 平均角速度 (扣零偏) 要夠小 | `still_gyro_mean` |
| 等速直線行駛 | 速度被歸零, 位置停在原地 | 剛離開靜止不久而估計速度還明顯不是 0 就不承認 | `still_speed_gate` / `_frac` / `_trust` |

速度那一道有三個保險, 都是實測踩到才加的:

* 門檻會加上 `still_speed_frac` x 離開靜止後的速度變化量 —— 加減速越劇烈,
  積分出來的速度越不準。
* 離開靜止後轉速超過 `still_speed_max_omega` (3 rad/s) 就不再否決 —— 高速自旋
  後估計速度會殘留 0.5 m/s 以上, 不能拿它否決真的停車 (實測滑出去 3.5 m)。
* 確認靜止之後, 要等 ZUPT 真的把估計速度壓到門檻以下才重新計數 —— ZUPT 的
  修正量太大時會被 `max_pos_correction` 縮小, 一次修不完 (實測滑出去 1.7 m)。

加速度那一道的門檻是固定的, 不隨零偏的不確定度放寬 (放寬的話煞車尾段會漏進來)。
開機靜止校正沒完成的時候, 加速度與角速度這兩道會自動關掉 (基準是錯的)。

### NHC 的份量 (`nhc_sigma`)

NHC 每一筆 IMU 做一次 (60 Hz), 而 skid-steer 轉彎時的側滑是持續好幾秒的同一個
偏差。把它當成每一筆獨立的量測, 一秒鐘就重複算了 60 次: 實測車子等速行駛、
剛開始緩轉的 2 秒內, NHC 把估計的**前進速度**拉掉 0.28 m/s (真實車速沒變)。

所以 `nhc_sigma` 是「側滑大小 x sqrt(相關時間 x 取樣率)」, 不是側滑本身。
10 趟 Isaac bag (各約 35 m) 的位置 RMS 平均:

| `nhc_sigma` | 0.15 | 0.5 | 1.2 | **2.0** | 3.0 | 不開 NHC |
| --- | --- | --- | --- | --- | --- | --- |
| 位置 RMS | 1.24 m | 0.95 | 0.66 | **0.53** | 0.59 | 1.25 |

### 改之前 vs 現在

Isaac 十二趟 (同一份測試腳本, 各約 35 m、200 秒, 注入已知零偏) 離線重放的平均:

| | 位置 RMS | 最大 | 行駛中被判成靜止 | 陀螺零偏誤差 | 加速度 y 零偏誤差 |
| --- | --- | --- | --- | --- | --- |
| 改之前 (隨機遊走, 無第二階段確認, `nhc_sigma` 0.15) | 1.81 m | 5.55 m | 11.0% | 0.94 mrad/s | 0.071 m/s² |
| 現在 | 0.52 m | 1.89 m | 0.3% | 0.16 mrad/s | 0.0085 m/s² |

十二趟每一趟都比改之前好 (最差的一趟 0.65 m)。同樣十二趟的乾淨 IMU (沒有注入)
是 0.47 m —— 注入的零偏對定位幾乎沒有殘留影響。最後一趟有線上的輸出可以對:
線上 0.45 m, 離線重放 0.43 m。

**這些門檻是對著同一份測試腳本的資料調的。** 等速直線那一道在原理上是推測
(讀數跟靜止完全相同)。換場地或換車要重新確認 —— 拿一份有真值的 bag 跑
`car_imu_noise/test/analyze_run.py` (模擬) 或 `test/replay_bag.py` (真車沒有
零偏真值, 只能看位置)。

## 重力怎麼扣 —— 最重要的一個選擇

IMU 量到的是**比力** (specific force), 靜止水平時 `az ≈ +9.81`。車身一旦傾斜,
重力就會漏進水平軸。`gravity_mode` 三選一:

| 模式 | 怎麼做 | 什麼時候用 |
| --- | --- | --- |
| `orientation` | 用訊息裡的 `orientation` 把加速度轉到世界座標再扣 `[0,0,g]` | Isaac (精確值) 或 9 軸 IMU。**預設** |
| `complementary` | 陀螺儀積分 roll/pitch + 靜止時用加速度校正 | 真車的 6 軸 IMU |
| `none` | 假設車身永遠水平 | 平地、短時間 |

`complementary` 有一個容易做錯的細節: 直覺上是「`|a|` 接近 g 的時候才用加速度
校正傾角」, 但那個測試幾乎沒有鑑別力 —— 0.5 m/s² 的水平加速度只讓 `|a|` 從
9.807 變成 9.820 (差 0.13%), 測試照過, 而它對應的**假傾角是 2.9 度**, 換算回去
剛好就是那個加速度本身。等於把誤差原封不動地繞回來。所以這裡的傾角校正是由
**靜止偵測**觸發的, 不是由 `|a|` 測試。離線實測: 用 `|a|` 測試 RMS 1.6 m,
改成靜止觸發 0.35 m。

## 零偏模型: 開機常數 + Gauss-Markov

```
讀數 = 真值 + b0 + b_dyn(t) + 白雜訊
db_dyn/dt = -b_dyn/tau + n_b          (bias_model: gm, 預設)
```

| | 怎麼處理 |
| --- | --- |
| `b0` 開機常數零偏 | 開機靜止校正量掉, 放在濾波器狀態**外面**, 之後不變 |
| `b_dyn` 慢變零偏 | 濾波器的狀態, 一階 Gauss-Markov; 停車時由 ZARU / 零加速度更新修正 |
| 白雜訊 | 扣不掉, 只寫進過程雜訊 |

`b0` 一定要拆出來: GM 的衰減項會把估計值往 0 拉, 作用在整個零偏上的話會把
已經量到的常數零偏也拉掉。所以開機校正沒完成 (`calib_timeout`) 的那一輪,
節點會自動退回 `rw` (隨機遊走) 並印警告。

`bias_model: rw` 是原本的隨機遊走 —— GM 在 `tau` 無限大時的特例。

### 參數怎麼來: 對靜止資料做 Allan variance 擬合

```bash
ros2 bag record -s sqlite3 -o imu_static /imu       # 車子完全不動, 2 小時以上
ros2 run car_loc_imu imu_fit_noise imu_static --plot allan.png
ros2 launch car_loc_imu imu_loc.launch.py noise_fit:=$PWD/imu_noise_fit.yaml
```

`imu_fit_noise` 不需要 ROS (`python3 -m car_loc_imu.fit_noise <bag 或 csv>`
也行), 輸出:

* `imu_noise_fit.yaml` —— `tau_bg` / `sigma_gm_bg` / `tau_ba` / `sigma_gm_ba`,
  以及這顆 IMU 需要的靜止偵測門檻。沒給 `noise_fit` 的話 launch 用
  [config/imu_noise_fit.yaml](config/imu_noise_fit.yaml), 裡面是還沒擬合過的
  預設值 (從原本隨機遊走的參數換算來的)。
* Allan 曲線圖 —— 量到的點、擬合的曲線、白雜訊與 GM 各自的貢獻。

要注意的事:

* **資料要夠長。** `tau` 要分辨得出來, 資料至少要 20 個 `tau`; 不夠的話工具會
  明講, 那時的 `tau` / `sigma` 只能當下限。
* **資料要真的靜止。** 有動作的話會被當成零偏漂移, 工具會直接拒絕。
* **Isaac 原始的 `/imu` 擬合不出 GM 項** —— 它沒有零偏模型。要在模擬裡驗證
  這整條流程, 用 `car_imu_noise` 把誤差加上去 (那個 package 只在模擬用)。
* 白雜訊密度只印出來對照, 不會自動改 `sigma_gyro` / `sigma_acc`: 那兩個是
  過程雜訊, 還要蓋住車體震動與模型誤差。

### 扣掉零偏之後的 IMU

`/imu_loc/imu_corrected`: 原始 IMU 的陀螺儀 z 與加速度 x/y 扣掉目前估計的
總零偏 (`b0 + b_dyn`)。白雜訊還在。

### 搬到真車

`car_loc_imu` 整包直接搬, **不要帶 `car_imu_noise`**。照順序:

1. 靜止錄 IMU 2 小時以上 → `imu_fit_noise` → 得到 `imu_noise_fit.yaml`。
2. launch 加 `use_sim_time:=false imu_topic:=<真車的 topic>
   noise_fit:=<上一步的檔>`。6 軸 IMU 再加 `gravity_mode:=complementary
   yaw_source:=gyro sigma_acc:=0.35`。
3. 確認 `forward_deg` (真車照 REP-103 的話是 0, 不是 -90)。
4. 開車, 看 status 的「靜止 xx%」跟實際停車比例對不對得上; 對不上就調
   `still_var`。擬合工具只保證門檻夠寬讓靜止過得了, 上限要靠這一步。
5. `nhc_sigma` 照 sqrt(IMU 取樣率 / 60) 縮放。

**還不能說「照搬就會動」:**

* 6 軸模式 (`complementary` + `gyro`) 只在合成資料上跑過; 第二階段確認與
  `nhc_sigma: 2.0` 都是在 `orientation` 模式的 Isaac 資料上調的。
* 6 軸模式的陀螺 x/y 零偏沒有扣: 開機校正算了三軸平均但只用 z, 互補濾波拿
  未扣零偏的 x/y 去積分傾角。**上真車前要先補。**
* 槓桿臂沒有補償。先用 `test/replay_bag.py <bag> --measure` 量, 超過 1 cm 就要補。

## 狀態與輸出

狀態 8 維: `p(2), v(2), yaw, b_gyro_z, b_acc(2)` (零偏是扣掉 `b0` 之後的動態
部分)。每個量測進來之前都先算 NIS (normalized innovation squared), 吃卡方閘門
的量測超過門檻就整個丟掉。

| topic | 內容 |
| --- | --- |
| `/imu_loc/odom` | 位姿 + 速度 + 共變異數 (主要輸出) |
| `/imu_loc/pose` | `PoseWithCovarianceStamped` |
| `/imu_loc/imu_corrected` | 扣掉估計零偏之後的 IMU |
| TF | `map -> base_link` (`publish_tf:=false` 可關) |
| `~/reset` | `std_srvs/Trigger`: 回到 `initial_pose` 並重新校正零偏 |

`evaluate` 報的不是平均誤差 (對純 IMU 沒有意義 —— 誤差是單調長大的), 而是:

* 誤差**第一次超過** 0.5 / 1 / 2 / 5 m 是在第幾秒、走了幾公尺
* 漂移率 (誤差 / 已行走距離, %) —— 慣性導航的標準指標
* 誤差隨時間的曲線 —— **呈階梯狀代表 ZUPT 真的有在動**, 呈直線代表沒停過車

## 出事的時候

| 症狀 | 通常是 |
| --- | --- |
| 開直線時位置停住不動 | 靜止判定太鬆, 等速直線被誤判成靜止。把 `still_var` 調小 |
| 停車時位置還在漂 | 靜止判定太緊, ZUPT 沒觸發。看 status 的「靜止 xx%」 |
| 加速度零偏 (`b_a`) 在衝刺前後一次跳 0.2 m/s² 以上 | 平順的直線加減速被判成靜止, 真實的加速度被當成零偏。確認 `still_acc_mean` 沒有被設成 0 |
| 陀螺零偏 (`b_g`) 在自旋結束後跳 2 mrad/s | 自旋後的慢轉被判成靜止。確認 `still_gyro_mean` 沒有被設成 0 |
| 等速直線時估計位置停在原地 | 等速直線的讀數跟靜止一樣。看 status 的「靜止否決 … 速度」有沒有在跳; 沒有的話檢查 `still_speed_gate` |
| 真的停車了估計卻還在滑 | 速度估錯太多, 被 `still_speed_gate` 否決。最多持續 `still_speed_trust` 秒; 常發生就把 `still_speed_frac` 調大 |
| 一開始就漂得很快 | 沒做開機靜止校正 (車一開始就在動)。看啟動時的警告 |
| yaw 一直轉 | `yaw_source:=gyro` 而陀螺零偏沒校正好。多停幾次讓 ZARU 修 |
| 車子明明在跑, 估計位置卻幾乎不動, 然後往側邊愈飄愈遠 | `forward_deg` 給錯, NHC 約束到前進軸。這台車要 -90 |
| 位置**一步就跳好幾公尺** (不是慢慢漂) | 過程雜訊沒有 `sigma_acc_omega` 那一項, P 被灌大 -> 速度偽量測的增益逼近 1。看 status 的「限幅」次數 |
| status 的「擋掉」次數很大 | 卡方閘門在擋正確的量測。`gravity_mode=complementary` 卻用小的 `sigma_acc` 最常見 |
| 原地自旋之後就整個跑掉 | 60 Hz 對 8 rad/s 以上的自旋不夠 (一步就轉 8 度以上)。這是取樣率的物理限制, 不是參數 |
| 停車時 ZUPT 有觸發, 但誤差沒變小 | **正常。** ZUPT 只讓誤差停止長大, 不會讓它變小 —— 純 IMU 沒有絕對位置參考 |
| 誤差幾十秒就好幾公尺 | 正常。看上面的表 —— 這就是純 IMU 的量級 |
| 位置飛到場外 | 共變異數發散。`v_max` 會夾住速度; 檢查 `/imu` 有沒有掉包或時戳跳動 |
