# car_loc_wheel — IMU + 四輪輪速的航位推算

```
/imu          ──> 扣重力 ──> 投影到車頭方向 ──┐
                                              ├──> 7 維 EKF ──> /wheel_loc/odom
/joint_states ──> 依名字取四輪 -> 取中位數 ───┘                  /wheel_loc/pose
                  └─> 同側前後輪轉速差 -> 打滑指標                TF map->base_link
```

**只訂閱 `/imu` 與 `/joint_states`。** 沒有地圖、沒有雷射、沒有相機, 也不 import
任何其他 package。

---

## 先回答問題: 只用 IMU 一定會飄嗎

**會。** 而且飄的方式很特別 —— 加速度計的誤差要**積分兩次**才變成位置:

    位置誤差 ~ 0.5 * b_a * t²

它是**時間**的函數, 跟車子有沒有在動完全無關。停在原地不動, 誤差照樣長。
0.01 m/s² (很小的偏差) 在 60 秒後就是 18 公尺。這不是參數沒調好, 是數學。

輪速改變的正是這一件事。**輪速是速度的直接量測, 不是積分出來的**:

| | 誤差的形狀 | 停著不動時 |
| --- | --- | --- |
| 純 IMU | `0.5·b_a·t²` (時間的二次式) | 照樣長 |
| IMU + 輪速 | `(尺度誤差 + yaw誤差)·距離` (距離的一次式) | **不長** |

### 真機實測 (Isaac, 2026-09-09)

`car_loc_imu` 與 `car_loc_wheel` **同時跑**、吃同一份 `/imu`, 由
`collect_data_node` 記到同一個 CSV 逐列比。227.5 秒, ground truth 走了 65.8 m,
51% 的時間靜止, 含 12 次自旋 (最高 13.4 rad/s) 與 slip_launch / 急煞:

| | 純 IMU (`car_loc_imu`) | **IMU + 輪速** | 倍數 |
| --- | --- | --- | --- |
| 位置 RMS | 2.531 m | **0.215 m** | **11.8×** |
| p95 | 5.374 m | 0.422 m | 12.7× |
| 最大 | 8.676 m | **0.512 m** | 17.0× |
| 漂移率 (最大/距離) | 13.18% | **0.78%** | 17× |
| yaw 誤差中位 | 0.074° | 0.069° | 一樣 |

**yaw 一樣**是預期的 —— 兩邊的 yaw 都來自 IMU 的絕對姿態, 輪速對朝向沒有貢獻。
差別**全部**在位置/速度那一路。

誤差成長的**形狀** (log-log 最小平方的指數):

| | 誤差 ~ t^p | 誤差 ~ d^q |
| --- | --- | --- |
| 純 IMU | **p = 2.27** | q = 0.74 |
| IMU + 輪速 | **p = 0.84** | q = 0.20 |

`p ≈ 2` 正是課本的 `0.5·b_a·t²` —— 加速度誤差積分兩次。加了輪速之後 p 掉到
0.84, 誤差不再跟時間走。**這個形狀的差別比「11.8 倍」那個數字重要**, 因為它
決定了時間拉長之後會變怎樣。

最直接的證據是把靜止段跟行駛段分開看 (誤差的總變動量 `Σ|Δe|`, 淨值會互相抵消):

| | 靜止 (115.9 s) | 行駛 (111.6 s) |
| --- | --- | --- |
| 純 IMU | 8.72 m → **0.075 m/s** | 68.42 m → 0.613 m/s |
| IMU + 輪速 | 1.14 m → **0.010 m/s** | 11.95 m → 0.107 m/s |

**純 IMU 停著不動的時候, 誤差還是以 0.075 m/s 的速率在亂走** (那是估計在真值
附近隨機遊走, 不是修正)。加了輪速之後靜止段幾乎完全凍住 —— 這就是 11.8 倍的
來源。

### 合成資料 (可隨時重跑)

`test/test_wheel_ins.py`, 180 秒**一路不停車**:

| | RMS | 最大 | 誤差 ~ t^p 的 p |
| --- | --- | --- | --- |
| 純慣性 (開迴路積分) | 2.97 m | 7.15 m | 1.42 |
| 純 IMU + ZUPT | 2.54 m | 6.17 m | 1.49 |
| **IMU + 輪速** | **0.11 m** | **0.25 m** | **1.11** |

合成資料量到的 `p` 比真機的 2.27 小, 因為那條 8 字形一直在轉, 而加速度計的零偏
固定在**車體**上 —— 假加速度的方向跟著車轉, 有一部分自己抵消掉了。真機那一輪有
長時間的直線與靜止, 零偏方向在世界座標裡比較穩定, 所以更接近課本的 2.0。

**差距取決於「多久停一次」**: 純 IMU 的抗漂移全靠 ZUPT, 只在停車時有效;
輪速則是一直有效。合成資料上走走停停差 12 倍、一路不停差 22 倍, 真機那一輪
(51% 靜止) 是 11.8 倍 —— 對得上。

### 但加了輪速還是會飄

輪速只給**速度**, 陀螺儀只給**角速度**, 兩個都還要積分一次才變成位姿。
長期來看主導項是 **yaw**, 不是輪速的尺度誤差:

    走了 d 公尺、yaw 差了 e 弧度 -> 側向位置誤差 ≈ d · e

走 100 m 而 yaw 差 1 度 = 1.7 m。要真的不漂只能靠絕對量測 —— 那是
`car_loc_camera` (相機) 與 `car_loc_lidar` (LiDAR) 在做的事。

## 用法

```bash
ros2 launch car_loc_wheel wheel_loc.launch.py
ros2 launch car_loc_wheel wheel_loc.launch.py evaluate:=true

# 真車 (6 軸 IMU, 沒有絕對姿態)
ros2 launch car_loc_wheel wheel_loc.launch.py use_sim_time:=false \
    imu_topic:=/imu/data gravity_mode:=complementary yaw_source:=gyro \
    sigma_acc:=0.35

# A/B: 關掉輪速, 看退化成純 IMU 差多少
ros2 launch car_loc_wheel wheel_loc.launch.py evaluate:=true enable_wheel:=false

# base_link 照 REP-103 (+X 是車頭) 的車; 這台 car.usd 不是, 預設已經是 -90
ros2 launch car_loc_wheel wheel_loc.launch.py forward_deg:=0.0
```

> **開始之前先讓車子停著一秒。** 開機靜止校正要在那裡把陀螺零偏量掉 ——
> 而 yaw 零偏乘上行走距離就是位置誤差。有輪速之後這一步比純 IMU 容易得多
> (「輪子不轉」就是靜止), 但還是要有那一秒。

四支, 分工不同, 要一起看:

```bash
cd src/car_loc_wheel

python3 test/replay_bag.py <bag 目錄>                    # 你自己錄的 bag
python3 test/replay_bag.py <bag 目錄> --measure

```

> 現有的 `car_run_data/isaac/bags/spin12` **沒有錄 `/joint_states`**
> (只有 `/imu` `/odom` `/lidar/point_cloud` `/yolo/pose`), 所以 `replay_bag.py`
> 跑不了它。要用這條路得重錄一次, 把輪速加進去。

| | 資料 | 能驗證什麼 |
| --- | --- | --- |
| `test_wheel_ins.py` | 合成 | 濾波器。**唯一能做「純 IMU vs IMU+輪速」對照的地方** (誤差模型是我們放的), 以及誤差成長的指數 |
| `test_node.py` | 合成 | **節點**: 參數接對了沒、兩條訊息流交錯、車頭軸、開機校正、感測器壞掉時的降級。用假的 `rclpy` 跑, 不需要 ROS |
| `replay_csv.py` | `car_run_data/sim_data.csv` | 真的 Isaac 資料, 但**沒有原始加速度** -> 只驗證「輪速 + 陀螺儀」那一半 |
| `replay_bag.py` | 你自己的 rosbag2 | 完整的一條路, 而且參數是對著**你的車**量出來的。`--selftest` 另外驗手刻的 CDR 解析 |

CDR 解析是手刻的 (為了不依賴 ROS), 所以驗過:
`/imu` 與 `/odom` 拿真的 bag 交叉驗證 —— 兩個 topic 各自解出來的 yaw 中位差
**0.038 度**, quaternion 範數 1.000000, `|a|` 中位 9.810。`/joint_states` 手邊
沒有真資料 (見下), 所以用 round-trip 補: 換三種 `frame_id` 長度把後面欄位的對齊
推移, 加上 velocity 是空陣列的情況。

錄 bag 的話:

```bash
ros2 bag record -o my_run /imu /joint_states /odom
python3 test/replay_bag.py my_run --measure
```

**參數不要用猜的。** `--measure` 量的每一項都直接對應一個參數:

| 量什麼 | 決定 |
| --- | --- |
| ground truth 的行進方向 vs yaw | `forward_deg` |
| 有效輪半徑 (對 ground truth 最小平方) | `wheel_scale` |
| 靜止時的輪速雜訊底線 + 誤判率 | `still_wheel` |
| 同側前後輪轉速差 vs 輪速誤差 | `slip_spread` / `slip_spread_max` |
| 輪速殘差 | `wheel_sigma` |
| 左右輪速差算的角速度 vs 真值 | 能不能用輪速算 yaw (這台車不行) |

## 三個感測器的分工是量出來的

### 輪速 → 前進速度。**不要拿它算 yaw**

skid-steer 轉彎時輪子一定在滑, 所以「左右輪速差 / 輪距」算出來的角速度是廢的。
量給你看 (`sim_data.csv`, 跟 ground truth 的 yaw 微分比):

| | |
| --- | --- |
| `r·(w_R − w_L)/track` 跟真實角速度的相關係數 | **0.41** |
| 最小平方法反推的「有效輪距」 | 0.18 m (幾何輪距是 0.25 m) |
| `/odom` 角速度 (≈ 陀螺儀) 跟真值的相關係數 | **0.997** |

相關係數在不同的資料上是 0.41 / 0.63 / 0.81 / 0.85, 反推的「有效輪距」則是
0.18 / 0.56 / **−0.51** / **−0.84** m —— **連正負號都不穩定**。這比單一個數字
更有說服力: 它不是「校不準」, 是那個模型在這台車上根本不成立。

端到端 (只換 yaw 的來源, 其他都一樣):

| yaw 從哪來 | 228 秒那一輪 RMS | 當前 sim_data.csv RMS |
| --- | --- | --- |
| **IMU 的絕對姿態** (Isaac / 9 軸) | **0.58 m** | **0.25 m** |
| 陀螺儀積分 (真車 6 軸) | 2.26 m | 0.56 m |
| 左右輪速差 | 11.85 m | 0.46 m |

倍數差很多 (20 倍 vs 1.8 倍) —— 因為當前那一輪只走了 5 公尺, 幾乎沒給誤差
累積的機會。**方向兩輪一致**, 倍數不要當規格。這就是為什麼這個 package 叫
「IMU + 輪速」而不是「輪速里程計」。

> 中間那一列 (陀螺儀積分) 在這份 CSV 上被低估了: 資料是 **20 Hz**, 而裡面有
> 12 次高速自旋 (最高 14.5 rad/s = **每筆轉 42 度**), 光是一階保持的離散化誤差
> `|w|·dt/2` 就累積 131 度。真的節點吃 60 Hz 的 `/imu`。

### 陀螺儀 → 角速度。加速度計 → 打滑時的備援

輪速壞掉的時候 (打滑、離地、撞牆) 由 IMU 撐著; 輪速正常的時候由輪速把 IMU 的
速度誤差壓掉。**兩邊壞的方式不一樣**, 這才是融合的意義。

### 側向速度 = 0 在這台車上幾乎是恆等式

量 ground truth 的側向速度 (乾淨行駛段, n=1129):

    中位數 0.0000 m/s, p95 0.0006 m/s, 最大 0.012 m/s

所以這裡**不像 `car_loc_imu` 把 NHC 當成一個偽量測再用卡方閘門擋** —— 直接把它
寫進狀態: 只有一個純量速度 `v` (沿車頭方向), 沒有側向速度這個自由度。少一個狀態、
少一次更新, 而且不可能發生 `car_loc_imu` 表 [CC] 那種「軸給錯比不開還糟 45 倍」
的事 (不過 `forward_deg` 還是要給對, 見下面)。

高速自旋 (|wz|>3) 時側向速度 p95 是 0.097 m/s —— 不是 0, 所以過程雜訊留了
`sigma_cross` 給它。給 0 的話 P 在側向會是奇異的, 之後任何量測都修不動那一維。

## 狀態 (7 維)

    x = [ p(2)   位置 (world)
          v      前進速度 (車體, 純量)
          yaw    朝向
          b_g    陀螺儀 z 零偏
          b_a    前進方向的加速度計零偏
          k      輪速尺度 (v = k·r·ω); **預設凍結** ]

**線上估 `k` 預設是關的** (`sigma_k: 0.0`)。理由是可觀測性: 要把尺度 `k` 跟
加速度計零偏 `b_a` 分開, 需要「加速度計看得到、但尺度誤差解釋不了」的運動。
走走停停的一般行駛裡這兩者幾乎共線, 打開之後 `k` 會去吸收 `b_a` 的誤差,
反而更糟。離線量一次, 當常數用。

## 輪徑尺度: 它跟**牽引狀態**有關, 不是幾何常數

尺度誤差是**系統性**的 —— 走 100 公尺就是幾公尺, 不會因為停車而消失。同一台車
的五份資料量出來:

| 資料 | n | scale | 殘差 std | 那一段車子在做什麼 |
| --- | --- | --- | --- | --- |
| `sim_data` Reposition | 923 | **0.932** | 0.060 | 控制器驅動 (有扭矩) |
| `sim_data` 嚴格直線 | 863 | 0.929 | 0.086 | 控制器驅動 |
| `sim_data.backup` | 1966 | 0.927 | 0.095 | 控制器驅動 |
| `sim_data` (較早的一份) | 1129 | 0.976 | 0.065 | 混合 |
| `spin12` | 312 | **1.008** | **0.0097** | 自旋後的**滑行** (沒有扭矩) |

**四份控制器驅動的都是 0.93, 只有滑行那一份是 1.008 —— 剛好等於幾何值。**
這正好就是物理:

    有扭矩 -> 輪胎一定有縱向滑移 (slip ratio), 輪子永遠比車快一點
             -> v/ω 偏小 -> 「有效半徑」比幾何值小
    滑行   -> 沒有驅動力, 滑移趨近 0 -> 量到的就是真正的幾何半徑

所以 1.008 不是「比較準」, 它是**另一個工作點**。定位時車子是被開著的, 要用有
扭矩的那個 —— 預設 **0.93**。

> 我一開始看到 spin12 的殘差小一個數量級, 就以為它最可信、把預設訂成幾何值
> 1.0。那是錯的 —— 殘差小是因為滑行本來就乾淨, 不代表那個工作點是車子平常
> 在跑的工作點。

端到端 (`test/replay_csv.py`, 214 秒那一輪):

| | RMS | 最大 |
| --- | --- | --- |
| scale 1.0 (幾何值) | 0.736 m | 2.115 |
| scale 0.976 | 0.720 m | 2.01 |
| **scale 0.93** | **0.684 m** | 1.941 |

要自己校就錄一段**正常開的直線**(不是滑行、不是自旋):

```bash
ros2 bag record -o straight /imu /joint_states /odom
python3 test/replay_bag.py straight --measure
```

`--measure` 會判品質: **n > 200 且殘差 std < 0.03** 才算數。

**線上估 scale 是關的** (`sigma_k: 0.0`)。可觀測性: 要把 `k` 跟加速度計零偏
`b_a` 分開, 需要「加速度計看得到、但輪速的尺度誤差解釋不了」的動作。走走停停的
一般行駛裡兩者幾乎共線, 打開之後 k 會去吸收 b_a 的誤差, 反而更糟。

## 打滑怎麼辦

228 秒那一輪是為了量打滑錄的, 裡面的輪速在那些時候是**大錯特錯**, 不是小雜訊
(當前的 sim_data.csv 沒有那麼極端的段落, 最大誤差只到 0.59 m/s):

| 同側 (前後輪) 轉速差 | 輪速誤差 中位 | p95 | 最大 |
| --- | --- | --- | --- |
| < 0.5 rad/s | 0.019 m/s | 0.118 | 0.52 |
| 0.5 – 2 | 0.047 | 0.182 | 2.25 |
| 2 – 5 | 0.029 | 0.282 | 2.95 |
| **> 5** | 0.012 | **3.84** | **6.20** |

**同一側的前後輪在幾何上必須同速** (skid-steer 沒有差速器, 而且轉彎時同側前後輪
走同一條軌跡)。所以「同側前後輪不同速」= 至少有一顆在滑 —— 這是輪速資料**自己
內部的矛盾**, 不需要 ground truth, 也不需要濾波器狀態。

三道防線:

| | 抓什麼 | 為什麼別的抓不到 |
| --- | --- | --- |
| **四輪取中位數** | 一顆輪子空轉 | 平均會被拉走 (一般行駛段殘差 std 0.095 → **0.051**, p95 0.243 → **0.105** m/s) |
| **同側轉速差 → 放大 R** | 單輪 / 單側空轉 | 卡方閘門要等誤差夠大才反應 |
| **卡方閘門** | 整側兩顆一起空轉 | 同側差看不出來, 只有跟 IMU 遞推比才知道 |

> 蓄意打滑那一段 (`spread > 2`) 中位數跟平均**一樣**, 因為那裡是整側一起滑 ——
> 任何統計量都救不了, 只能靠後兩道防線降權。中位數的價值在一般行駛時的單輪空轉。

**中間漸進, 但上限要給得很大 —— 這是實測改出來的。** 打滑是連續的, 所以
`[slip_spread, slip_spread_max]` 之間線性內插: 同側差 0.5–2 rad/s 時輪速誤差
p95 只有 0.18 m/s, 直接丟掉太浪費。

但**超過上限之後要幾乎完全不信**。三份真實資料一起掃 `wheel_sigma_slip`
(位置 RMS, 越小越好):

| `wheel_sigma_slip` | 0.5 | **1.5** | 2.5 | 4.0 | 6.0 | **10.0** | 20.0 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `sim_data` | 0.481 | **0.684** | 0.505 | 0.432 | 0.401 | **0.380** | 0.402 |
| `sim_data.backup` | 8.234 | 7.408 | 6.955 | 6.649 | 6.498 | **6.381** | 6.114 |
| `spin12` | 6.290 | 6.184 | 5.784 | 5.480 | 5.302 | **5.163** | 5.122 |

**三份都是越大越好, 而原本的預設 1.5 剛好卡在最差的位置。** 那個非單調正是
「信一半」最糟的症狀: 量測爛到會把狀態拉走, 但 sigma 又沒大到讓增益趨近 0。
現在預設 **10.0** (增益 ~1e-4, 效果等於丟掉)。

為什麼不乾脆真的丟掉: 留著極大的 sigma, **卡方閘門仍然看得到它** —— 而閘門
連續兩秒擋不下來正是逃生口 (`wheel_reject_time`) 該啟動的訊號。真的丟掉的話
那個訊號也一起沒了。

實測:

| | 228 秒那一輪 | 當前 sim_data.csv |
| --- | --- | --- |
| 全開 | **0.58 m** RMS | **0.25 m** RMS |
| 關掉 slip_gate (只剩卡方閘門) | 0.69 m | 0.28 m |

合成資料上兩者幾乎等價 (卡方閘門一個人就夠), 真資料上差 16% —— 因為真的打滑
不像合成的那麼乾脆。

## 靜止偵測: 輪速讓這件事不用猜

`car_loc_imu` 的靜止偵測要同時看陀螺儀、加速度大小、**加速度的變異數**, 因為純
慣性量測分不出「靜止」與「等速直線」(兩者角速度都是 0, 合力都是重力)。那個偵測器
很難調 —— 太鬆會在直線行駛時誤觸發 ZUPT 讓位置停住, 太緊則停車時完全不觸發。

輪子沒有這個含糊: **輪子在轉就是在走。** 實測 (228 秒那一輪, 4557 筆;
當前 sim_data.csv 與 spin12 也是同樣的結果):

| `still_wheel` | 判為靜止 | 其中車子其實在動 (>0.1 m/s) |
| --- | --- | --- |
| 0.2 rad/s | 30.1% | **0.00%** |
| **0.5 (預設)** | 32.6% | **0.00%** |
| 1.0 | 34.9% | 0.00% |
| 2.0 | 37.0% | 0.48% |

靜止時各輪 `|ω|` 的 p95 是 0.062 rad/s (= 0.005 m/s), 所以預設值 0.5 留了
8 倍的餘裕還是幾乎不誤判。

### 但它有先天的半拍延遲 —— 而且這會咬人

**加速度是速度的導數, 所以起步瞬間加速度已經滿了、輪子才剛要轉。** 那一兩筆會被
判成「靜止」, 然後「靜止時加速度應該是 0」那個更新就把真實的加速度當成零偏吃進去。

實測 (`test_wheel_ins.py`, 真實零偏 0.02 m/s²):

| | 估出來的 `b_a` | 位置 RMS |
| --- | --- | --- |
| 沒有殘差上限 | **0.0301** (差 50%) | **0.912 m** |
| 有殘差上限 (`zero_accel_max: 0.5`) | 0.0203 | 0.268 m |

**一筆就夠了。** 那時 `P[b_a]` 已經被前面上百筆更新壓到很小 (增益只有 0.011),
但 innovation 有 1.47, 乘起來就是 0.016 的零偏誤差 —— 而且一路不停的話**再也
沒有機會修回來**。

上限之所以是對的: 車子如果真的靜止, 扣完重力的加速度**依定義**接近 0, 殘差大就
表示「靜止」這個前提已經不成立了。**這不是離群值判斷, 是前提檢查** —— 所以它是
一個絕對門檻, 不吃卡方閘門 (P 的大小跟這件事無關)。

## 輪速不可以被卡方閘門永久鎖死

這是 `test/test_node.py` 抓到的一個真問題, 值得單獨講。

速度的不確定度 `P[v]` 在 ZUPT 之後被壓到 `zupt_sigma²` (1e-4), 之後只靠過程雜訊
`qa·dt` 慢慢長回來 (60 Hz 下每步 4e-5)。所以濾波器的速度信念一旦錯得夠遠 ——
加速度計壞掉、`gravity_mode` 配錯、傾角估歪、或一段打滑之後輪子重新咬地 ——
卡方閘門會**一直**擋: 要等 `P[v]` 長到蓋得住那個 innovation 才放行, 0.5 m/s
的落差要等 **14 秒**。

實測 (加速度計整個壞掉, 輪速從 0 階躍到 0.6 m/s, 12 秒):

| | 估計速度 | 輪速被擋掉 |
| --- | --- | --- |
| 不設逃生口 | **0.000 m/s** (車子在估計裡完全沒動過) | 600 筆, **全部** |
| `wheel_reject_time: 2.0` | 0.602 m/s | 363 筆, 強制接受 3 次 |

所以: **輪速連續被擋掉超過 2 秒就強制接受一次** (R 放大 3 倍, 走過去而不是跳
過去)。一次離群是量測的問題, 連續兩秒都對不上就是濾波器自己錯了 —— 而輪速是
直接量測, 另一個選項是純靠遞推。

**門檻要用時間, 而且要給得長。** 打滑期間閘門本來就**應該**一直擋, 那不是病態:

| `wheel_reject_time` | 合成資料 RMS (含 4 段打滑) |
| --- | --- |
| 0.33 秒 | 0.304 m (打滑中被強制接受 3~4 次) |
| **2 秒** | **0.114 m** (打滑期間完全不介入) |

## ZUPT / ZARU 在這裡的角色變了

實測 (合成資料, 左邊走走停停 / 右邊一路不停):

| | RMS | yaw 最大 |
| --- | --- | --- |
| 全開 | 0.025 / 0.114 m | 0.65° / 3.05° |
| 沒有 ZUPT / ZARU | 0.080 / 0.155 m | 1.82° / 4.29° |

在**走走停停**那條上 ZUPT 的資訊幾乎是重複的 —— 輪速本來就會說「現在沒在動」。
`sim_data.csv` 上更明顯 (RMS 0.58 vs 0.59, 完全在雜訊裡)。

它們真正的價值在三件事:

1. **ZARU 修陀螺零偏。** 這是輪速做不到的 —— 輪速對 yaw 沒有任何資訊。
   實測 (人工加 2 mrad/s 零偏, yaw 只靠積分): 有 ZARU RMS 2.26 m, 沒有 2.67 m。
2. **輪速掉線時的備援。** 那時就退回純 IMU 了, 節點會警告。
3. **位置錨定。** 停久了 ZUPT 把速度歸零, 但位置的共變異數還是會慢慢長成隨機
   遊走; 錨定把它按住。

跟 `car_loc_imu` 一樣, ZUPT / ZARU **不吃卡方閘門** —— 依據是一個跟濾波器狀態
無關的獨立判斷。拿閘門擋它等於「越迷路越拒絕修正」。差別在這裡的依據**強得多**:
誤判率 0.00%, 而慣性靜止偵測要靠變異數去猜。

## `forward_deg` 一定要給對

`base_link` 的 +X 量到「車頭」的角度 (度)。REP-103 說 +X 是車頭, 但 **`car.usd`
不是** —— 它 +X 朝左、車頭 -Y (`car_teleop/cmd_vel_bridge.py` 裡也寫著同一件事),
所以是 **-90**。

從 `sim_data.csv` 量出來的佐證: 車子在動的時候
`atan2(dy_gt, dx_gt) − gt_yaw = -90.0°` (中位數, n=1718)。

這個 package 裡「側向速度 = 0」是**寫進狀態**的結構性假設, 所以軸給錯不是
「約束錯一個軸」而是「整台車的運動學都錯了」—— 估計裡的車會往垂直於實際行進的
方向跑。`replay_bag.py --measure` 的第 [1] 項會直接量給你。

## 輸出

| topic | 內容 |
| --- | --- |
| `/wheel_loc/odom` | 位姿 + 速度 + 共變異數 (主要輸出) |
| `/wheel_loc/pose` | `PoseWithCovarianceStamped` |
| TF | `map -> base_link` (`publish_tf:=false` 可關) |
| `~/reset` | `std_srvs/Trigger`: 回到 `initial_pose` 並重新校正零偏 |

`odom.twist.twist.linear.x` 是**車頭方向**的速度 (跟 `/cmd_vel` 的慣例一致),
不是 `base_link` 的 x 軸。

`evaluate` 報的是**漂移率 (誤差 / 已走距離)**, 不是誤差 vs 時間 —— 加了輪速之後
誤差跟距離走, 用時間當橫軸會被「你停了多久」污染。它還會分開統計靜止段與行駛段
的誤差變動: **靜止段的誤差應該幾乎不長**, 那是輪速最直接的好處。

## 出事的時候

| 症狀 | 通常是 |
| --- | --- |
| 位置往垂直於實際行進的方向跑 | `forward_deg` 給錯。這台車要 -90 |
| 走直線距離一直偏長 / 偏短 | `wheel_scale` 沒校。`replay_bag.py --measure` 量一次 |
| 停車時位置還在漂 | 靜止偵測沒觸發。看 status 的「靜止 xx%」跟實際停車比例對不對得上 |
| 打滑之後整個跑掉 | status 的「打滑放寬」是 0 的話, 輪子名字可能對不上 (同側配錯對)。看啟動時的警告 |
| status 的「擋掉」次數很大 | 卡方閘門在擋正確的輪速。`wheel_sigma` 太小, 或 `gravity_mode=complementary` 卻用小的 `sigma_acc` |
| status 的「強制」次數不是 0 | 輪速連續兩秒跟遞推對不上 -> 濾波器錯了。通常是加速度計那一路壞了 (`gravity_mode` / `forward_deg` 配錯), 偶爾幾次是長時間打滑之後重新咬地 |
| yaw 一直轉 | `yaw_source:=gyro` 而陀螺零偏沒校正好。多停幾次讓 ZARU 修 |
| 「N 秒沒有收到 /joint_states」 | Isaac 的 `ROS2PublishJointState` 沒在發。這時等於純 IMU 在跑, 誤差回到 t² |
| 開機一直卡在「靜止校正中」 | 車子沒停穩, 或 `/joint_states` 還沒來 (訊息裡會寫是哪一個) |
| status 的「輪速時戳」偏移很大 (>50 ms) | 兩個 topic 的時戳來源不一致。offset 是 a·dt 的速度誤差, 50 ms × 1 m/s² = 0.05 m/s |
| 誤差走 100 m 就 2 公尺 | 正常。看上面的漂移率 —— 這就是航位推算的量級 |
| 位置永遠不會收斂回真值 | **正常。** 航位推算沒有絕對參考, 誤差是不可逆的。要收斂得用相機或 LiDAR |
